# Implementation report — EU Health-Claim Campaign Escrow

**Result:** the single-campaign Studionet IC and tests are implemented. The main live clear/payout, flagged/revision/refund, timeout/refund, access-control, exact-funding, and invalid-deposit-refund flows all passed on hosted Studionet (chain ID `61999`). The existing feasibility-spike contract/test/results remain unchanged; the top-level README was updated to describe both the new build and preserved spike.

- `tests/test_live_campaign.py` — new no-mock hosted Studionet integration tests.
- `tests/test_campaign_direct.py` — new synthetic Direct Mode policy/state tests; mocks are explicitly identified in the file and are not counted as live evidence or settlement.

- `IMPLEMENTATION_REPORT.md` — this as-built report.

Unchanged preserved spike files: `contracts/HealthClaimSpike.py`, `tests/test_live_spike.py`, and `RESULTS.md`.

## Test status and classification

- **Live, real Studionet, no mocks:** all three functions in `tests/test_live_campaign.py` passed individually. They exercised live DG SANTE and product-page retrieval, GenLayer semantic evaluation and validator consensus, exact funding/access checks, one real `CLEARED` payout, real `FLAGGED`/revision/refund, and the actual deadline/timeout refund. Each live test took about 7–8 minutes.
- **Direct Mode, synthetic/mocked:** `python -m pytest tests/test_campaign_direct.py -v` — **6 passed**. The fixtures cover duplicate-row normalization, supported/incomplete seller-page markers, unavailable/conflicting sources, bounded verdict/state paths, one revision/deadline checks, and a validator callback rejecting a changed normalized snapshot. These do **not** establish real Web Access, network consensus, or EVM settlement.
- **Syntax/deployment:** the new IC deployed and executed on Studionet; Python syntax compilation also passed.
- The original no-mock spike remains documented in `RESULTS.md`; it was not rerun as part of these escrow tests.

## Remaining limitations / unverified paths

1. The `PAYOUT_FAILED` / `REFUND_FAILED` callback and `retry_failed_settlement` logic is implemented but was not tested by deliberately forcing an external child transfer to fail.
2. A live `INCONCLUSIVE` from real unavailable/conflicting external evidence was not induced; those fail-closed branches were exercised with synthetic Direct Mode fixtures. Live happy-path, flagged-path, and timeout/refund evidence were real.
3. Direct Mode in `genlayer-test==0.29.2` tried to download `genvm-universal v0.3.0-rc7`, which returned 404. The direct test pins a published `v0.2.12` runner and passed. Hosted Studionet integration was unaffected. A transient Studio API 502 also occurred in an early attempt; the live test helper retries read/poll errors, and the final individual live runs passed.
4. This is testnet-only and not a legal certification. Product-condition evidence is seller-declared and the contract rubric is intentionally narrow. No production deployment, frontend, or separate backend service was created, per scope.

**This application is an evidence-based campaign settlement mechanism, not legal advice or legal certification.**
